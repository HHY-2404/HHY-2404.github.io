攻擊偵測自動開單

Kali → 偵測 → MantisBT

用 Kali 對實驗室主機發動掃描與暴力破解，自己寫偵測程式抓出來，並自動在問題追蹤系統開單，不需要人一直盯著終端機。

nmap 掃描→scapy 偵測器（systemd）→report_issue.py→MantisBT REST API
hydra 暴力破解→Fail2ban 封鎖→自訂 action→MantisBT 開單
  • 偵測器做成 systemd 服務，故障時自動重啟；Windows 主機端另用工作排程器開機執行。
  • MantisBT 依主機分專案（Ubuntu、Rocky/CentOS、Windows 監視），開單內容含來源 IP 與被掃的埠。
  • 第一次 nmap 掃描就發現內部 DNS 服務對同網段開放，已停用並修補。

踩到的坑：sudo 與 systemd 不會讀使用者的 ~/.bashrc，環境變數抓不到 API 金鑰，改成從權限受控的設定檔讀取。多網卡主機上 scapy 要明確指定網卡，否則會監聽錯介面。

Incident research

資安事件研究

整理四種 WordPress／PHP 入侵手法的目的、手法與影響。案例 A 為實際參與排查，B、C 為研讀過往事件的調查報告，D 為公開漏洞研究。客戶名稱、帳號與 IP 均已移除。

A｜寄生 SEO 後門

實際參與排查
  • 目的：借用網站的搜尋排名推銷垃圾內容，同時保留遠端控制權
  • 手法：偽裝成 SEO 外掛並從外掛清單隱藏自己；劫持 sitemap、產生垃圾頁面；特定網址可免密碼以管理員登入，另一條路徑可遠端執行任意程式；指揮伺服器位址存在區塊鏈合約上，封鎖網域也擋不住
  • 影響：網站實質上完全淪陷，需移除後門、全面更換密碼與金鑰並清查殘留

我做的事：從備份清查帳號與登入紀錄，在隔離環境靜態閱讀後門程式碼（不執行），整理成鑑識報告。

B｜Webshell 後門

研讀事件報告
  • 目的：在伺服器上建立長期可用的遠端操作入口
  • 手法：盜用管理員工作階段進入；植入檔案管理型 webshell 並偽裝成圖片、複製多份；把惡意碼注入既有的核心檔案
  • 影響：攻擊者可瀏覽、修改檔案與執行指令，潛伏約三週才被發現

學到的重點：清除要分三種處理：純惡意檔刪除、被注入的檔案只切除惡意段落、核心檔用官方版覆蓋；換 SALT 才能讓偷走的 cookie 失效。

C｜帳號入侵與多層持久化

研讀事件報告
  • 目的：挾持網站並確保管理員清不乾淨
  • 手法：盜用合法管理員帳號 → 安裝多個惡意外掛 → 建立會自動恢復的排程 → 建立大量假帳號並提權
  • 影響：後門分散在多處，只清一個點沒有用，駐留約 54 天

學到的重點：「入侵途徑」決定修完會不會再被同一招打，事件整理時要獨立成一個欄位。

D｜PHP-CGI 參數注入

CVE-2024-4577
  • 目的：不需帳號密碼，直接取得伺服器執行權
  • 手法：在網址中夾帶 PHP 設定參數，讓 PHP-CGI 執行請求內容裡的程式碼
  • 影響：繞過 WordPress 整層防護，可讀取設定檔、植入後門

學到的重點：底層 PHP 版本與執行模式也要納入資產盤點，WAF 可在更新前先擋已知手法。
